## Structure

- `index.html` — the hub. A masthead, a JS-generated "Diese Woche" panel (driven by the saved profile — see the App shell section) and the full page register. There is no hand-maintained `<ul>` of links any more: the register is built from `DW.PAGES` in `assets/app-shell.js`, so **a new page must be added to that array** to appear here and in the slide-over Index. The register is two-level (level bucket → type sub-group) — see the App shell section.
- `study-plan.html` — the static phased plan (kept as the rationale) plus, at the top, a JS-generated timeline that splits the six phases backward from the saved exam date and marks the phase containing today. Falls back to the static table when no exam date is set. **Keep this in sync** if the target exam date, scope, or phase order changes — the phase weights also live in `assets/app-shell.js` (`PHASES`).
- `assets/app-shell.css` + `assets/app-shell.js` — the shared app chrome (top bar, slide-over Index, first-visit splash, exam countdown, EN/DE UI-language toggle, 📖 page glossary) and the **single source of truth for all design tokens**. See the "App shell & the Register design system" section below. Loaded first on every current-format page, ahead of that page's own stylesheet. `app-shell.js` also injects `assets/glossary.js` + `assets/glossary-data.js` and `assets/interactive.js` at runtime.
- `assets/interactive.js` — turns any print-first workbook into a fillable quiz **in place** (so phones can use them — no PDF needed). Self-gates on `.section .exercise .answer-block`. Adds a **Print ⇄ Interaktiv** toggle + a live "N/total bearbeitet · N richtig" counter after `.doc-header`. In interactive mode each `.exercise` gets an input; the `.answer-block` is hidden until checked. Short gap-fills (`coreAnswer` ≤ 3 words, no circled digits, from an `.answer-block` not a `.model-answer-block`) are **auto-graded** — normalised compare against `/`- and `oder`-split variants, with Levenshtein ≈16 %-of-length typo tolerance → *Richtig / Fast / Noch nicht*. Everything sentence-length reveals the model answer + a *Hatte ich ✓ / Nochmal* self-grade. Answers + results are saved per page in `localStorage['dw.wb:<pathname>']`; the mode is `localStorage['dw.workbookMode']` (`"print"` | `"interactive"`), defaulting to **interactive on ≤ 640 px screens**, print otherwise. Print/`@media print` output is the untouched original layout **except** every `.answer-block` (not `.model-answer-block` — those still sit next to their free-writing prompt, unchanged) is pulled out of its exercise and collected into one **"Lösungen" section at the end of the page** (`buildAnswerKey()`, `#dw-answer-key`, `page-break-before: always` in print), so a page can be filled in fully before checking anything — the exercise itself still shows its blank + `.qnum`, just not the answer beside it; each key entry is prefixed with the same `.qnum`. This applies to both non-interactive **on-screen** viewing and the printed PDF — interactive mode is untouched (still reveals each answer inline on check, no bottom key shown there). The bar also carries a "Lösungen im Druck ausblenden" checkbox (`localStorage['dw.printAnswers']` `"0"`/`"1"`, default show) that adds `body.dw-noprint-answers`, which now hides the `#dw-answer-key` section (not individual blocks, since they're already relocated) for a clean write-only worksheet PDF. Because it parses `.answer-block` (label + answer + optional `.why`), **keep authoring answer boxes exactly as the format below specifies** — the interactive layer is generated from them, never separately maintained.
- `assets/print-workbook.css` — the shared stylesheet for every printable workbook/exam-prep page. Reuse its existing classes (`doc-header`, `level-badge`, `tip-box`, `cheatsheet`, `section`, `exercise`, `write-line`, `write-area`/`write-area.tall`, `answer-block`, `model-answer-block`, `audio-controls`, etc.) — do not invent new ones or add inline `<style>` blocks. If a genuinely new reusable component is needed, add it here so every page benefits. It no longer defines `:root` tokens or the `body.level-*` accents — those moved to `assets/app-shell.css`; this file only consumes them. Body accent classes: `level-a1`/`level-a2`/`level-b1`/`level-b2`/`level-exam` for level-specific pages, plus `level-ref` (neutral grey) for cross-level reference pages that aren't tied to one level — see `workbooks/connectors-reference.html`.
- `assets/listening.js` — Web Speech API (`speechSynthesis`)-based text-to-speech for Hörverstehen pages: `speakText(id)`, `stopSpeaking(id)`, `toggleTranscript(id, btnEl)`. There is no hosted audio anywhere in this repo and none should be added — this is the mechanism, permanently. Voice quality is device-dependent, so the script ranks the installed German voices (`scoreVoice` — prefers "natural"/"neural"/Google/premium/enhanced/Siri, penalises "compact"/eSpeak), auto-picks the best, and injects a `.voice-picker` row (once per page, after `.controls`/`.tip-box`/`.doc-header`/`main`/`.st-wrap`) so the user can override it; the choice is remembered per device in `localStorage['listening.voiceURI']`. `buildVoicePicker()` is idempotent and re-run repeatedly (poll, `visibilitychange`, and right after `speakText`) because on phones — especially an installed PWA — `getVoices()` is often empty until the first `speak()` runs and `onvoiceschanged` never fires; the first tap/keypress anywhere also fires `primeVoices()` (a muted utterance) to force the list to populate. When fewer than 2 German voices are known it still shows a fallback row (current voice + an "ⓘ Stimmen" button that `alert()`s the full installed-voice dump + iOS/Android install paths) rather than rendering nothing. It also speaks sentence by sentence (more natural prosody + avoids Chrome's ~15 s cut-off, with a `pause()`/`resume()` keep-alive). Genuinely non-robotic output still requires the user to install an Enhanced/Premium German voice in their OS settings — the picker just surfaces whatever is installed. (On iOS every browser, Chrome included, shares Safari's voices.)

- `reels/` — a third, separate interactive trainer (`g: "interactive"` in the register, own bucket entry, not merged into `vocab/` or `situations/`): a minimal swipe-through revision mode, deliberately with **no grading UI of its own (no Again/Hard/Good/Easy)** — just word → meaning (or Satzkreis/Satzleiter base+station → Modellantwort), tap (or swipe up) to reveal, tap/swipe up again to advance, **swipe down to go back** to the previous card (re-shown already revealed, since you've seen it). Card changes animate as a short slide (`playCardAnim()` in `practice.html` toggles `.rl-anim-up`/`.rl-anim-down`, `@keyframes rl-slide-up`/`rl-slide-down` in `reels.css`) rather than snapping instantly — state and content update **synchronously on every tap/swipe with no blocking lock**, and the animation is purely cosmetic on top, restarted via a forced reflow if re-triggered mid-flight; an earlier version gated input on an `animating` flag until each ~400ms transition finished, which silently dropped taps/swipes fired in a quick burst ("racing" through cards) and left the deck stuck partway with no summary — don't reintroduce that gate. The card, quiz and "Fertig" screens are three interchangeable **screens**, not stacked page sections — `.rl-screen` (`reels.css`) fixes all three (`#rl-stage`/`#rl-quiz`/`#rl-end`) to the exact same on-screen rectangle below the app-shell topbar + this page's own back-link bar, each internally `overflow-y: auto` for when its own content (e.g. a long review list) is taller than the screen. Switching between them is always an in-place swap, never something requiring the page itself to be scrolled — the page has no scroll of its own at all now. The exact top offset (`--rl-top-offset`) has a static CSS fallback but is corrected at runtime by `setTopOffset()` in `practice.html`, which polls for `.dw-topbar-spacer` (app-shell's topbar is injected by a deferred script, so it may not exist on the first tick) and measures the real combined height, since the generic `.controls` styling isn't a fixed height and stacking app-shell's topbar with this page's own bar made a static guess unreliable. The swipe listeners also call `preventDefault()` on `touchmove` once vertical intent is detected (not just `touchend`), belt-and-suspenders against a touch device trying to scroll something that, now, never scrolls anyway. This whole fixed-screen approach replaced an earlier one that positioned quiz/end in normal document flow below the card and forced `window.scrollTo(0, 0)` when switching — that was reported as the deck going "stuck" on the last card with the summary invisible below the fold; treating every screen as sharing one fixed slot removes the whole scroll-position class of bug rather than patching around it. Added as a quick experiment ("try it for a couple of days and see if it helps") rather than a fully worked-out system — keep it that way unless it proves out. `reels/index.html` (pick a source — Vokabeln / Satzkreis / Satzleiter — plus level/count for vocab) and `reels/practice.html` (the player) share `reels/reels.css`. `reels/index.html`'s vocab options end with a one-line pointer to `vocab/index.html` ("Reels zeigt hier keinen eigenen Fortschritt…") — added because the two are easy to conflate (both live under "Interaktiv üben" and both touch vocab data), and Reels deliberately has no progress UI of its own (see below), so the real progress dashboard (hero + per-level module cards) only lives on the Vokabeltrainer's own main page. Once the deck is done, `reels/practice.html` runs one lightweight in-session **multiple-choice check** (skipped when the deck has fewer than 4 cards, or any time via "Check überspringen"): each card's `front` reappears with 4 shuffled choices (its own `back` + 3 distractors drawn from other cards' `back` values in the same deck), instant right/wrong highlight, no persistence beyond the in-memory `quizCorrect` counter for the final score line. That lands on a **"Fertig"** screen — score line + the same review list as before, "Nochmal" (restart this deck) or "Neue Runde" (`index.html`) — which also starts a 12 s auto-redirect to `index.html` ("hier bleiben" cancels it), so a session flows on to picking the next set instead of dead-ending. Sources: vocab cards are built from `vocab/data/{a1,a2,b1,b2}.js` (same `window.VOCAB_RAW` used by `vocab/`, loaded read-only, no shared IndexedDB/profile); sentence cards are built from `workbooks/satz-data.js` (see above). Reuses `assets/listening.js` for an optional per-card 🔊. Each card reveal calls `DW.logActivity("reels", "card", {src})` so it counts toward `progress.html`'s **Gesamt** total, but — like the vocab/situations trainers had at first — it does not yet have its own `progress.html` section; a natural future addition if the format sticks. **Vocab quiz answers are graded into the real Vokabeltrainer state** — `reels/practice.html` also loads `vocab/js/db.js` + `vocab/js/srs.js` and, on every vocab-source quiz answer, writes an FSRS review exactly like `vocab/js/practice.js`'s own MCQ mode does (`correct` → grade `good`, wrong → grade `again`, `mode: "reels-quiz"` in the review log so it's distinguishable from `vocab/practice.html` sessions), under whichever profile is currently active in `localStorage['vocab.activeProfile']` — reels has no profile system of its own, it just borrows that one read-only. If no vocab profile is active (or the stored name no longer exists), it silently skips the writes and the quiz still works, just ungraded; the `#rl-quiz-credit` line under the question counter says which case is happening ("Zählt für Vokabeltrainer-Profil „X“" or "Kein Vokabeltrainer-Profil aktiv"), since a review is easy to write silently and hard to notice is missing. This is a deliberate exception to reels' "no persistence of grades" design — added because reels reusing the vocab dataset but not counting toward `vocab/stats.html`'s due/learned/weak-words picture defeated the point of practicing there; the Satzkreis/Satzleiter quiz (no corresponding vocab entries) is unaffected and still fully ephemeral. `typeof VocabDB === "undefined"` (not `window.VocabDB`) is the correct guard for whether `db.js` loaded — its top-level `const`/`function` declarations don't attach to `window` in a classic (non-module) script, only to the shared script-level scope.
  - **"Prüfen" is a heuristic, not a grader** (this repo has no backend / LLM): per-station regex checks in `KREIS_CHECK`/`LEITER_CHECK` for verb-final position in subordinate clauses, verb-second after a fronted clause, comma placement, and "did you actually build the required construction" (e.g. Futur needs `werden` + final infinitive; Passiv needs `werden` + Partizip / `… worden`; indirekte Rede needs a Konj-I form). Every message is a soft `⚠ … wohl/scheint`, never a verdict; a standing disclaimer says creative-but-correct answers can be flagged. Plus an **offline spellcheck**: Typo.js + the vendored German Hunspell dictionary (`workbooks/vendor/`), lazy-loaded on first "Prüfen" (~1.1 MB `de_DE.dic`, then browser-cached; needs http(s), silently skipped on `file://`). Words from the card's own base + model answer are whitelisted to cut false positives. A future optional "Mit KI prüfen" button (user's own Anthropic key in `localStorage`, direct browser call) is planned as a separate additive change.
  - **Visual design deliberately diverges from the ruled/flat "Register" system for this one page** (Yatender liked the flashcard look of a Gemini-generated "WortSchatz" mockup and asked for it here): `reels.css` gives `.rl-card` large `border-radius`, a soft drop shadow and a two-tone gradient background, themed per grammatical gender for vocab cards (`.rl-theme-der/die/das` — der blue, die rose, das a dark mustard-gold, each a standalone saturated colour pair in `reels.css`, not tied to `--lv-*`/`--signal`, chosen so the four card themes read as distinct colours at a glance rather than pale tints) with `.rl-theme-neutral` (a violet, matching `body.level-mixed`'s own accent) for non-nouns and for Satzkreis/Satzleiter decks; `practice.html`'s `buildVocabDeck()` carries the entry's `article` through as `gender` on each deck card, and `renderCard()`/`themeClassFor()` swap the theme class per card. No per-word icons/emoji were added (the vocab data has no such field, and guessing one per word risked being wrong) — the gender colour coding carries the "delight" instead. The end-of-deck MCQ (`.rl-quiz-choice`) is intentionally **text-only, no icons of any kind**, including in any future rework of this page — an icon there could visually match a themed card's colour/appearance and give away the correct choice before reading the German. The reel stage/quiz screens carry real side padding (22px) on top of `.rl-card`'s own max-width so the card never touches the screen edges on a phone.
- `workbooks/vendor/` — third-party libs vendored so the repo stays static/offline: `typo.js` (Typo.js 1.2.4, Hunspell spellchecker, exposes global `Typo`), `de_DE.aff` + `de_DE.dic` (the `dictionary-de` / igerman98 Hunspell dictionary, comment lines stripped). Only `workbooks/satztraining.html` uses these so far.
- `cheatsheets/`, `web workbooks/` — older reference material, unrelated to the current system.
- `vocab/` — interactive vocabulary trainer, A1–B2, separate system from the print-first workbooks below (see "Vocabulary trainer" section).
- `situations/` — interactive conversation/situation trainer, B1–B2, sibling system to `vocab/` (see "Situations trainer" section).

## App shell & the "Register" design system

Every current-format page — all print-first pages, `index.html`, `study-plan.html`, and both trainers — loads a shared app shell. The whole integration is two lines:

```html
<link rel="stylesheet" href="<REL>/assets/app-shell.css">   <!-- BEFORE the page's own stylesheet -->
...
<script defer src="<REL>/assets/app-shell.js"></script>      <!-- just before </body> -->
```

`<REL>` is the path to the repo root: `.` at root, `../..` for `workbooks/B1/…` and `exam-prep/B1/…`, `..` for `workbooks/connectors-reference.html` and the trainers. The script injects everything else at runtime; the one-off `inject_shell.py` that added these lines in bulk is not checked in.

**What the shell provides**
- A fixed top bar: a `≡ Index` button, a breadcrumb (from `document.title` + the `body.level-*` class), a **📖 page-glossary** button, an **EN / DE** UI-language toggle, and an exam-countdown chip. Screen-only — hidden in `@media print` and marked `no-print`.
- **UI-language toggle** (`localStorage['dw.uiLang']`, `"de"` default | `"en"`; `DW.uiLang()`, `DW.setUiLang()`, `DW.onUiLangChange`): flips the **chrome only** — top bar, Index panel labels (the `en` fields on `LEVEL_BUCKETS` / `GROUPS`), countdown, filter placeholder — via the `t(de, en)` helper + `refreshChrome()`. It never touches exercise content (the German *is* the material). The splash, mini-editor and the hub "Diese Woche" panel are still German-only — a future extension if wanted.
- A **📖 "Nachschlagen" panel** (`assets/glossary.js` + `assets/glossary-data.js`, both injected by `app-shell.js` via `loadScript`; opens on the 📖 top-bar button). Two parts: (1) a **free word search** — checks the curated grammar glossary (`window.DW_GLOSSARY`, ~140 entries) *and* the vocab trainer's dictionary (`vocab/data/{a1,a2,b1,b2}.js`, lazy-loaded from `DW.ROOT` on first search, ~5,860 words with article/plural/translation/example), plus one-tap links to dict.cc / LEO / Wiktionary for the raw query (always shown, so anything not in-repo is one click away); (2) below it, the `DW_GLOSSARY` terms that appear on the current page, each with a one-line English gloss, with a filter. Read-only — never rewrites the page. To cover a new grammar term, add it to `glossary-data.js`; general vocabulary comes from the vocab JSON. On a workbook page the dictionary data needs a network fetch the first time (it's outside the vocab service-worker scope).
- A slide-over **Index** ("jump anywhere") and the hub register share one renderer (`DW.renderRegister`), now **two-level**: a top bucket per CEFR level (`LEVEL_BUCKETS` in `assets/app-shell.js`: Interaktiv üben · A1 · A2 · B1 · B2 · Referenz & Pläne — each page lands in exactly one bucket via that entry's `match` fn), and within a bucket the rows are sub-grouped by `GROUPS` (Grammatik / Prüfungstraining / Üben / Referenz / Ältere Hefte), with the sub-heading hidden when a bucket has only one group. Live filter (hides empty groups *and* empty buckets); opens on the `≡` button or the `/` key.
- Every row except the `g: "interactive"` trainers (vocab/situations/satztraining — ongoing spaced-repetition practice with no "finished" state) carries a **done checkbox** (`.dw-check`), a small square before the title. It's manual — click toggles `localStorage['dw.pageDone:<pathname>']` (`"1"` or removed) and the row + bucket count re-render immediately. A page whose own exercises already have recorded results (`dw.wb:<pathname>`, written by `interactive.js`) but isn't checked off yet gets a quiet filled-dot "begun" hint instead of an empty box — this never auto-checks the box, it's advisory only. Each bucket header shows a `done/total` count next to its label (`dw-bucket-count`, computed over the checkable pages in that bucket). Helpers: `pagePathname(pg)`, `readManualDone`/`writeManualDone`, `pageStarted` in `assets/app-shell.js`.
- A first-visit **splash**: name → current level → optional exam date. Put `data-dw-nosplash` on `<body>` to keep the top bar but skip the splash — the two trainers do this because they have their own profile systems.
- A **mini editor** ("Profil & Termin") from the countdown chip, to change name/level/date later.

**Design tokens live only in `assets/app-shell.css`.** `:root` there is the single source of truth for the palette, the `--lv-*` level colours, the `body.level-*` `--accent`/`--accent-bg` overrides, and the `--serif`/`--sans` stacks. `print-workbook.css`, `vocab/vocab.css` and `situations/situations.css` no longer define those — they keep only their own component tokens (`--again/--hard/--good/--easy`, `--card-bg`). Do not re-add a palette `:root` to those files.

**The "Register" look** (this is what keeps it from looking like a generic AI site — hold the line):
- Typographic, **zero web fonts**: system serif (`--serif`) for display, system sans (`--sans`) for UI. The printable worksheet body keeps its existing Georgia-first serif untouched.
- Ruled, not shadowed: hairline rules, `border-radius` 0–2px. The only shadow in the system is on the slide-over Index.
- Chapters are numbered (`01`, `02`, …).
- Colour is a coding system, not paint: a level's colour appears only as a badge, a 3px side-rule, or a link hover — never a fill.
- One warm signal colour, ochre (`--signal` `#b9740b`), is reserved for *live* things only: the countdown, "du bist hier", today's date.

**Profile** — `localStorage['dw.profile']` = `{ name, level: "a1"|"a2"|"b1"|"b2", examDate: "YYYY-MM-DD"|null, createdAt }`. Read with `DW.readProfile()`; write via `DW.writeProfile(p)` or the mini editor (both fire `DW.onProfileChange`).

**Generated timeline** — `DW.buildTimeline(examISO)` splits the six `PHASES` (weights `setup 1, B1-Grammatik 4, B1-Prüfung 2, B2-Grammatik 6, B2-Prüfung 3, Konsolidierung 2`; total 18) proportionally across the weeks remaining (min 1 wk/phase, floor 6 wk), lays the ranges out backward from the exam date, and flags the phase containing today. Both `study-plan.html` and the hub "Diese Woche" panel consume it. If phase weights or order change, update `PHASES` in `assets/app-shell.js` **and** the static table in `study-plan.html` together.

**Adding a page**: add it to the `PAGES` array in `assets/app-shell.js` (`{ p: root-relative path, t: title, g: group key, lv: level for the tag colour, tag: short label }`) — that is what surfaces it in the hub register and the Index — then add the two shell lines to the page. The `g`/`lv`/`tag` fields also route the page to a top-level `LEVEL_BUCKETS` bucket (e.g. an exam-prep page is `g: "exam"` + `tag: "B1"` and lands in the B1 bucket; `g: "interactive"` lands in "Interaktiv üben"; `g: "reference"` in "Referenz & Pläne"). If you introduce a genuinely new level or section, add a `LEVEL_BUCKETS` entry too.

**Responsive wide tables** — `app-shell.css` adds a screen-only safety net: `.cheatsheet` scrolls its own overflow, and wrapping a wide `<table>` in `<div class="dw-table-scroll">` makes it scroll inside a bordered box instead of stretching the page (used on `study-plan.html`). Both collapse back to plain full-width tables in `@media print`.

**`vocab/sw.js`**: `../assets/app-shell.css`, `../assets/app-shell.js`, `../assets/glossary.js`, `../assets/glossary-data.js`, `../assets/interactive.js` and `../assets/listening.js` are in `PRECACHE_URLS`; bump `CACHE_NAME` (currently `vokabeltrainer-v19`) whenever any of them changes.

## The print-first workbook format (core convention — apply to every new page)

Every current-format page (`workbooks/A2/workbook-7-*`, `workbook-8-*`, `workbook-15-*`, `workbook-16-*`, all of `workbooks/B1/`, `workbooks/B2/`, all of `exam-prep/`) follows this exact pattern. When adding a new one, copy an existing file of the same type as the literal structural template rather than inventing markup from scratch:

- Links `assets/app-shell.css` then `assets/print-workbook.css` via relative paths, and `<script defer src="…/assets/app-shell.js"></script>` before `</body>` (see the App shell section); `<body class="level-a2|level-b1|level-b2|level-exam">` sets the accent color.
- `.controls` (no-print): Index link, Print button, Prev/Next links. `.doc-header`: `.level-badge` + `<h1>` + `.doc-meta`.
- `.tip-box` (no-print) explaining how to use the page.
- `.cheatsheet` box with grammar rules or a format overview, using plain `<table>`s.
- `.section` blocks, each with a `.section-title` (including its exercise number range) and a `.section-note`.
- Each `.exercise`: `.qnum`, `.prompt`, then `.write-line` (single blank) or `.write-area` / `.write-area.tall` (sentence/essay length), **then an `.answer-block` immediately below** with `.label` "Lösung" + the correct answer + an optional `.why`. Author it this way in the HTML source every time — `interactive.js` parses `.answer-block` right after each exercise (see above) and depends on that structure for auto-grading. What Yatender actually *sees*, though, differs by mode: in interactive mode the answer reveals inline on check, same as always; in print/non-interactive mode (both on-screen and the printed PDF he makes on his iPad via Noteful) `interactive.js` now pulls every `.answer-block` out and collects it into one "Lösungen" section at the end of the page instead, so he can fill in a whole page before checking any of it. `.model-answer-block` (free-writing/essay tasks) is the exception — it stays put next to its prompt, since it's a worked example to read alongside the prompt, not a spoiler to defer.
- Cloze passages: circled-number spans (`&#9312;` etc.) inside one `.write-area.tall`, with one combined `.answer-block` listing every gap's answer.
- Free-writing tasks (letters/essays): `.model-answer-block` instead of `.answer-block` (no single correct answer), plus a self-assessment checklist.
- `.doc-footer` (no-print) mirrors the controls-bar nav links.
- When inserting a new page into the sequence, update the prev/next links in both the file before it and the file after it.

## Vocabulary trainer (`vocab/`)

A separate, fully interactive app (not print-first) — spaced-repetition vocab practice across A1–B2, ~5,860 words. No backend, no build step: plain HTML/CSS/JS, static-hostable like the rest of the repo.

- **Source of truth**: `vocab/data/{a1,a2,b1,b2}.json`, one flat array per level. Schema per entry: `{id, word, article, plural, forms, full, translation_en, examples: [{de, en?}], level}` (`plural` is for nouns, `forms` holds verb principal parts — e.g. "gibt ab, hat abgegeben" — mutually exclusive with `plural`). Regenerating these files requires re-running the one-off extraction scripts (not checked into the repo) against: the official Goethe A1 (Start Deutsch 1) and A2 wordlist PDFs (word + German example only, no English — English was backfilled from the B1 set where the same word recurs there), a B1 Anki deck (`B1_Wortliste_DTZ_Goethe...apkg`, richest source: word + article + plural + English + up to 9 example sentence pairs), and the "B2 Der-Die-Das" 1,479-noun sub-deck of a TELC B2 grammar Anki deck (word + article + English, no example sentences). None of these source files are checked into the repo — treat `vocab/data/*.json` as the durable artifact.
- **No hosted audio** — same rule as the rest of the repo. `vocab/practice.html` includes `assets/listening.js` directly and reuses `speakText(id)` for the listening practice mode (writes the current word/sentence into a hidden `#tts-source` span, then calls `speakText('tts-source')`).
- **Storage**: IndexedDB only (`vocab/js/db.js`), no server. Three object stores: `profiles` (name-based, no auth), `cards` (per-profile SRS state keyed by `${profile}::${entryId}`), `reviews` (append-only log used for the stats page). Multiple profiles can coexist on one device; the active profile is remembered in `localStorage` under `vocab.activeProfile`.
- **Scheduler**: FSRS-6 in `vocab/js/srs.js`, adapted to day granularity (this app shows each due card at most once per day, so same-day relearning steps are skipped) and using the published FSRS-6 default parameters (not personally optimized — that needs an optimizer fit to review history via `open-spaced-repetition/ts-fsrs`, out of scope for a no-build vanilla-JS app). Cards store `difficulty`/`stability` instead of the old SM-2 `interval`/`ease`; old cards without `stability` are treated as brand-new on their next review (a deliberate, un-migrated reset — acceptable since it's a personal deck, not something to build migration machinery for). "Again" always forces a 1-day due date regardless of the computed FSRS interval, since a lapsed card should come back soon and this app has no same-day relearning queue to do that otherwise.
- **Practice modes** (`vocab/js/practice.js`): flashcard self-grade, multiple choice, fill-in-the-blank (cloze, built from a real example sentence), type-the-German-word, listening, and dictation (hear a full example sentence via TTS, type exactly what you heard — graded on the whole sentence with punctuation stripped, and on a miss shows a word-by-word diff plus the sentence's English translation). "Gemischt" (mixed) picks a random mode per card, falling back to flashcard when an entry lacks the data a mode needs (e.g. no `translation_en` → skip MCQ/type; no usable example → skip cloze/dictation).
- **Targeted practice by id**: `practice.html?...&ids=<id1,id2,...>` bypasses the normal due/fresh queue selection (`buildQueueFromIds` in `practice.js`) and builds a session from exactly those entry ids, in mode-picker order. Used by the weak-words "Nur diese üben" link below; reusable for any other "practice just these words" entry point.
- **Reel-style navigation** (`practice.html`, all six modes): advancing used to be a fixed `setTimeout` (250ms on a correct answer, up to 2400ms on dictation) with no way to slow down or revisit a mistake — replaced with a **"Weiter →" button** plus swipe-up/swipe-down (and ArrowUp/ArrowDown/Enter on a keyboard), matching `reels/`'s forward/back feel. `session.index` (how many cards are actually graded/recorded) and `session.viewIndex` (what's on screen right now) are tracked separately: `finishCard()` snapshots the just-answered card's rendered HTML into `session.history[]` **before** appending the Weiter button, so re-inserting that HTML later via `innerHTML` on going back strips all live listeners automatically — a frozen, read-only replay that can never re-grade or re-record anything. `goForward()`/`goBack()` walk `viewIndex` through that history; forward only ever re-enters the live, editable next card once `viewIndex` catches up to the frontier (`session.index - 1`) — before that, or on an unanswered live card, it just steps through history or no-ops (you still have to actually answer a card via its own UI; swiping can't skip that). Touch swipe (`wireSwipe()`) is a **fast-flick heuristic on `touchend`** (distance + speed), not a `touchmove`-intercepting drag like `reels.css`'s `.rl-screen` — this page is normal scrolling document flow (some modes, e.g. dictation's diff block, run taller than the viewport), so `touchmove` is never `preventDefault()`-ed here, unlike reels' fixed-height screens which never scroll at all. `.card` also picked up a bigger `border-radius` + soft shadow to read a little closer to reels' feel.
- **Pages**: `vocab/index.html` (profile picker + a **progress overview** + level/mode/session-length setup), `vocab/practice.html` (session runner), `vocab/stats.html` (14-day bar chart, 15-week activity heatmap, streak, per-level accuracy, a **"Wortschatz nach Niveau" mastery breakdown**, and a weak-words list — the entries with the most incorrect reviews, each linking into a targeted `ids=` practice session — all computed client-side from the `reviews`/`cards` stores; requires the `data/*.js` scripts to be included on the page, same as the other two). The mastery breakdown (`renderLevelBreakdown` in `js/stats.js`) answers "how much of A1/A2/B1/B2 is left" per level: total words in that level's dataset (`VocabData.byLevel[lvl].length`) split into **gemeistert** (card `stability` &ge; `MASTERY_STABILITY_DAYS` = 21 — FSRS expects you to still recall it after 3 weeks without review, a legible round threshold, not a universal definition), **in Arbeit** (a card exists but hasn't reached that stability yet), and **noch nicht begonnen** (no card record at all), rendered as a thin two-segment bar (`--good` = mastered, `--accent` = in progress, unfilled track = not started) plus a text legend including a `% noch offen` figure (== not yet mastered, so words still "in Arbeit" count toward it too, not just untouched ones). `vocab/index.html`'s setup screen now opens with the same idea at a glance, once a profile is picked: a dark gradient **`.progress-hero`** banner (inspired by the same Gemini "WortSchatz" mockup that shaped the `reels/` redesign — see above) showing overall % mastered across all four levels with a gold-to-green fill bar, plus Wörter/Gelernt/Fällig stat tiles (`.stat-tile`, reused from the session-summary component). Below it, **one `.level-card` per CEFR level** (`.level-card-a1/a2/b1/b2`, tinted with the exact same `--lv-a1`/`--lv-a2`/`--lv-b1`/`--lv-b2` colours used everywhere else in the repo — badges, side-rules — so "which colour means which level" stays consistent site-wide; this is *not* the same colour axis as `reels.css`'s der/die/das gender theming): a level badge + title + one-line description, a **Gemeistert / In Arbeit / Fällig** stat triple for the whole level, a two-segment progress bar (dark = gemeistert, translucent = in Arbeit — an earlier version showed only gemeistert, which made real review activity that hadn't yet crossed the mastery threshold invisible as a flat 0%; both segments and the "In Arbeit" stat exist specifically so recent practice reads as progress before a word is fully mastered), and a **"20-Wörter-Module" row** — the level's word list sliced into fixed 20-word chunks in dataset order (`moduleChunks()`/`MODULE_SIZE` in `js/app.js`, purely computed on the fly, no stored module state), pointing at the first chunk that isn't fully mastered yet (or the last one if the whole level is done), with its own mini progress badge and a **"Start Modul N"** button that jumps straight into `practice.html?...&ids=<those 20 entries' ids>` via the existing targeted-practice mechanism (same `ids=` param the weak-words list uses) — bypassing the normal due/fresh queue to drill exactly that chunk. `renderProgressOverview()` in `js/app.js` duplicates the mastery calculation from `js/stats.js`'s `renderLevelBreakdown` rather than sharing it (same precedent as `situations/js/srs.js`; **keep `MASTERY_STABILITY_DAYS` = 21 in sync in both files if it ever changes**) — `stats.html`'s own simpler `.level-mastery-block` bars are untouched and still used there. Unlike the due-summary line and level chips further down (which scope the *next mixed session*), the hero and level cards always cover all four levels/the whole level — it's "how much is learned", not scoped to what you're about to practice. Styling lives in `vocab/vocab.css`, a sibling to `assets/print-workbook.css` but intentionally separate since this isn't a print page (same `--accent` per-level convention, different components). All three pages now also load `assets/app-shell.css` first (shared tokens + the global top bar) and carry `data-dw-nosplash` on `<body>`; `vocab.css` keeps only trainer-specific tokens/components.
- **Installable / offline (PWA)**: `vocab/manifest.json` + `vocab/sw.js` (cache-first service worker, scope `vocab/`) + `vocab/js/register-sw.js` (included at the bottom of all three pages) make the trainer installable to a phone home screen on both Android and iOS and fully usable offline — everything it needs (data is already loaded as `vocab/data/*.js`, not fetched) is precached. Icons live in `vocab/icons/` (`icon-192.png`, `icon-512.png`, `apple-touch-icon.png`, generated from `icon-source.svg` via `magick`). When adding a new page under `vocab/` or a new JS/CSS asset it depends on, add it to `PRECACHE_URLS` in `vocab/sw.js` and bump `CACHE_NAME` so returning users pick up the change. Note: service workers require a real HTTP(S) origin — they will not register over `file://` or in some sandboxed preview browsers; test via a local server (e.g. `python3 -m http.server`) or the deployed site.
- Content-accuracy requirements below apply here too, but note the A1/A2 example sentences and B2 nouns come from official/curated third-party lists rather than being generated — if you add new levels or regenerate data, keep flagging provenance (official wordlist vs. generated) rather than presenting everything as equally authoritative.

## Situations trainer (`situations/`)

A sibling app to `vocab/` — same no-backend, IndexedDB + FSRS-6 architecture — but for practicing *producing a full response in a real-life situation* rather than isolated words. Built because nothing else in the repo drills that skill: workbooks drill grammar, `vocab/` drills words, and the exam-prep speaking guide is print-and-read rather than something you practice repeatedly.

- **Why it's shaped this way**: this repo is intentionally backend-free, so there is no way to auto-grade open-ended spoken/typed German (that would need an LLM call). Instead of faking a grade, each card follows the vocab trainer's self-graded flashcard pattern: read/hear the situation → answer in your own words (out loud, or typed into a scratch textarea that is never saved) → reveal a model response + phrase bank → self-rate Again/Hard/Good/Easy, same FSRS-6 spacing as `vocab/`.
- **Source of truth**: `situations/data/{b1,b2}.json`, one flat array per level, hand-written (not extracted from a source deck/PDF — see below). Schema per entry: `{id, level, category, category_label, situation_de, situation_en, model_response, phrase_bank: [{de, en}]}`. `situations/data/{b1,b2}.js` are generated from the `.json` files (same `window.SITUATIONS_RAW.<level> = [...]` wrapper pattern as `vocab/data/*.js`, for the same file:// / CORS reason) — regenerate with a one-off `json.dumps(..., ensure_ascii=False, separators=(',',':'))` pass over the `.json` after editing it, don't hand-edit the `.js`.
- **8 categories** (`category` key → `category_label`): `beim-arzt` (Beim Arzt), `im-restaurant` (Im Restaurant), `am-arbeitsplatz` (Am Arbeitsplatz), `reisen-planen` (Reisen & Planen), `wohnen-beschwerden` (Wohnen & Beschwerden), `behoerden-termine` (Behörden & Termine), `soziales-einladungen` (Soziales & Einladungen), `meinungen-diskussion` (Meinungen & Diskussion) — 3 B1 + 3 B2 cards each, 48 total. Content provenance: no suitable Anki deck or source book was found (situation/dialogue-shaped content isn't really Anki-deck-shaped — existing German decks, including the ones behind `vocab/`, are word/phrase flashcards, not scenario dialogues), so these were written from scratch rather than extracted. Extensible — adding more cards to the JSON (same schema, new `id`s) is the expected way to grow this, no code changes needed.
- **No hosted audio** — same rule as the rest of the repo. `situations/practice.html` includes `assets/listening.js` directly and reuses `speakText(id)` to read the situation prompt aloud (writes it into a hidden `#tts-source` span, then calls `speakText('tts-source')`).
- **Storage**: IndexedDB, own database (`situations-trainer` in `situations/js/db.js`) — deliberately *not* shared with `vocab/js/db.js`'s `vocab-trainer` database, even though both run on the same origin, to keep the two trainers fully independent. Profiles are separate from the vocab trainer's, but `situations/js/app.js` reads (never writes) `localStorage['vocab.activeProfile']` to suggest the same profile name as a placeholder, as a convenience.
- **Scheduler**: `situations/js/srs.js` is a verbatim copy of `vocab/js/srs.js` (FSRS-6, day-granularity) — it was already fully generic (keys off `entry.id`/`entry.level`, no vocab-specific coupling), so it's duplicated rather than shared, matching this repo's existing precedent of `vocab.css` being an intentionally separate sibling of `assets/print-workbook.css` rather than a shared include. Keep both copies in sync if the scheduler itself is ever changed.
- **Single interaction mode**: unlike `vocab/`'s six practice modes, there is only one card type here (situation → your attempt → model answer + phrase bank → self-grade) — the constraint above (no auto-grading) is what a quiz-style mode would need, so there's no MCQ/cloze/type mode to build here.
- **Pages**: `situations/index.html` (profile picker + level/category/count setup — category chips are built dynamically from the loaded data's `category`/`category_label` pairs, not hardcoded in the HTML), `situations/practice.html` (session runner), `situations/stats.html` (14-day bar chart, 15-week activity heatmap, streak, per-level and per-category breakdown, and a "Situationen zum Wiederholen" list — the cards with the most Nochmal/Schwer grades, each linking into a targeted `ids=` practice session — computed client-side from the `reviews` store via `js/stats.js`, a direct port of `vocab/js/stats.js`). Since situations cards are self-graded on the FSRS Again/Hard/Good/Easy scale rather than vocab's binary correct/incorrect, "correct" here is redefined as grade good/easy (`isPositive()`), and the breakdown adds a category axis (situations' primary organizing dimension) alongside the level one; `SitDB.getReviews(profile)` was added to `js/db.js` to support it (mirrors `VocabDB.getReviews`). Linked from `index.html`'s setup screen and `practice.html`'s session-summary screen ("Statistik ansehen"), same placement as the vocab trainer. No PWA/offline support yet (straightforward to add, same pattern as `vocab/manifest.json` + `sw.js` + `register-sw.js`, just not built for v1). Styling lives in `situations/situations.css`, a close sibling of `vocab/vocab.css` (same tokens/chips/profile-grid/grade-row, copied not shared) plus new components: `.situation-context`, `.your-turn` (scratch textarea), `.model-response-block`, `.phrase-bank-block`, and the stats-page components (`.stats-tiles`, `.heatmap`, `.bars`, `.breakdown-row`, `.weak-card-row`, also copied from `vocab.css` rather than shared). Both pages load `assets/app-shell.css` first and carry `data-dw-nosplash`, same as the vocab trainer.

## Content-accuracy requirements

This is real exam-prep material.

- Every exercise and answer key must be correct standard Hochdeutsch — double-check case endings, verb position, and irregular forms before finalizing.
- Caveat telc format claims ("exact task counts can shift between test versions — check the current telc Modellsatz") rather than stating them as guaranteed fact.
- For any multiple-choice or lettered-matching exercise, **deliberately vary which letter is correct across items.** Content generation has a known failure mode of always writing the correct option first (letter "a") — before considering such content done, list the correct letter per item and confirm it isn't clustered on one letter.
